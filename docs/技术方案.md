# 基于 CARLA 的多机位 DVS 事件流数据集采集技术方案

## 1. 项目概述

### 1.1 目标
构建一个多视角、多场景的 DVS（Dynamic Vision Sensor）事件流数据集，覆盖车辆与行人目标，支持事件相机目标检测、跟踪、3D 感知等任务的训练与评测。

### 1.2 核心设计决策

| 决策项 | 方案 | 理由 |
|---|---|---|
| 事件生成方式 | **CARLA 原生 `sensor.camera.dvs`**（0.9.13+） | 免二次仿真，事件与仿真时钟天然对齐 |
| 运行模式 | **同步模式**（`synchronous_mode=True` + `fixed_delta_seconds`） | 多传感器帧对齐、事件时间戳可信 |
| 采集架构 | 自车环视 DVS + 路侧固定 DVS 混合 | 覆盖车载感知与智能交通路侧感知两类应用 |
| 传感器配对 | 每个 DVS 配一台同分辨率 RGB 相机 | RGB 帧用于自动化打标（bbox 投影）与可视化对照 |
| 数据存储 | `.h5` 紧凑存储（t, x, y, pol）+ JSON 标注 | 事件数据稀疏，h5 比 csv 节省 5–10 倍空间 |
| 规模化 | 多 CARLA 实例并行（每实例采不同 route/天气） | 单机吞吐约 1–2 小时/千帧多机位，需并行 |

### 1.3 事件产生的前提约束
DVS 只在亮度变化时产生事件，**静止目标与静止背景不产生事件**。因此：
- 自车必须持续运动（自主巡航控制器，非静止 spawn）；
- 只保留速度 > 0.1 m/s 的目标标注；
- 路侧相机视角应面向车流/人流密集区域（路口、斑马线）。

**角色划分**：CARLA Server 单进程承载场景与所有传感器；采集 Client 独立进程（甚至独立机器）负责回调攒批与落盘，避免回调内做重计算导致传感器丢帧。

## 4. 详细实现

### 4.1 世界与同步配置
```python
settings = world.get_settings()
settings.synchronous_mode = True
settings.fixed_delta_seconds = 0.05      # 20 Hz
settings.no_rendering_mode = False
world.apply_settings(settings)
traffic_manager.set_synchronous_mode(True)
traffic_manager.set_global_distance_to_leading_vehicle(2.5)
```

### 4.2 DVS 传感器工厂（参数化配置）
```python
DVS_PRESETS = {
    'ego':    dict(res=(640, 360),  fov=90,  pos_th=0.25, neg_th=0.25, refractory=0.5),
    'road':   dict(res=(1280, 720), fov=70,  pos_th=0.25, neg_th=0.25, refractory=0.5),
    'lowlight': dict(res=(640, 360), fov=90,  pos_th=0.10, neg_th=0.10, refractory=0.3),
}
```
- **阈值**：0.25 为默认；低光照预设用 0.10 模拟真实传感器高灵敏度档；
- **refractory_period_ms**：0.3–0.5，限制单像素最高触发频率，贴近真实芯片（如 DAVIS346 约 1 MHz/pixel 级但受带宽限制）；
- **曝光参数**（`iso`、`fstop`、`exposure_mode`）与 RGB 同档，保证 DVS 事件与 RGB 亮度变化一致。

### 4.3 相机布局
| 机位 | 挂载 | 位姿 | 分辨率 | 用途 |
|---|---|---|---|---|
| front_dvs | ego 前保险杠 | x=+2.0, z=1.5 | 640×360 | 前向感知主视角 |
| left_dvs / right_dvs | ego 左右后视镜位 | y=±0.9, z=1.5, yaw=±90° | 640×360 | 侧向行人/骑行者 |
| rear_dvs | ego 车尾 | x=−2.0, yaw=180° | 640×360 | 后向跟踪 |
| road_dvs ×N | 路口路灯杆 | z=6m, pitch=−25° | 1280×720 | 路侧密集视角 |

所有 DVS 与同位 RGB **严格同分辨率同内参**，保证 bbox 可从 RGB 直接迁移到事件坐标系。

### 4.4 交通生成策略
- 车辆：60–100 辆 autopilot，覆盖 Town01–Town10 六种地图拓扑；
- 行人：30–50 个 walker，用 `carla.WalkerControl` 直接驱动（**不使用 `controller.ai.walker`**：它要走导航网格，Town03 的导航数据不完整，服务端路径搜索会递归到爆栈 exit 0xC00000FD）；
- 自车：关闭 autopilot，使用简单 PID 巡航（恒速 8–15 m/s + 车道保持），保证持续运动——**静止自车 = 无事件**；
- 场景随机化：`world.set_weather()` 遍历 {ClearNoon, CloudyNoon, SoftRainSunset, WetSunset, ClearNight}，光照覆盖正午/黄昏/夜晚，路面干湿。

### 4.5 数据采集主循环（核心代码）
```python
sensor_queues = {name: queue.Queue() for name in camera_names}
for sensor, name in sensors:
    sensor.listen(lambda d, n=name: sensor_queues[n].put((time.time(), d)))

while frame < total_frames:
    world.tick()
    ts_sim = world.get_snapshot().timestamp.elapsed_seconds
    for name, q in sensor_queues.items():
        _, data = q.get(timeout=3.0)
        if name.endswith('dvs'):
            ev = np.frombuffer(data.raw_data,
                dtype=[('x','u2'),('y','u2'),('t','i8'),('pol','?')])
            buffer[name].append((ts_sim, ev))
        else:  # RGB 同时落盘供打标
            save_png(name, ts_sim, data)
    # bbox 投影（世界 → 相机坐标 → 像平面）
    labels = project_bboxes(world, sensor_transforms, min_speed=0.1)
    label_buffer.append((ts_sim, labels))
    frame += 1
```

### 4.6 标注流水线
1. **每 tick** 取所有 actor 的 3D bbox（`carla.BoundingBox`），过滤速度 < 0.1 m/s；
2. 世界坐标 → 传感器坐标（`sensor.get_transform().get_inverse_matrix()`）→ 相机内参投影 → 裁剪到像平面；
3. 输出 COCO 风格 JSON（`t, x, y, w, h, category_id`）或 1MPX 事件格式；
4. 遮挡/截断标志：bbox 超出像平面比例 > 0.5 标记 truncated。


### 4.8 规模化并行
- 单机：单 CARLA 实例 + 8 机位约 **1–2 秒/帧**（含落盘），每小时约 3000–5000 帧 episode；
- 集群：Docker 封装 CARLA Server + Collector，每实例采不同 (town, weather, route, seed) 组合，参考 CARLA Garage 210 实例并行范式；
- 种子管理：`random.seed(episode_id)` 保证可复现。

## 5. 质量控制与验收标准

| 检查项 | 标准 |
|---|---|
| 时间戳完整性 | 事件时间戳单调递增，无跳变；与仿真时钟偏差 < 2 ms |
| RGB–DVS 对齐 | 同机位同帧目标 bbox 在事件帧与 RGB 帧 IoU > 0.8（抽检） |
| 事件密度 | 每帧每相机事件数 1k–200k，过低（<1k）判为场景静止丢弃 |
| 类别覆盖 | 每类目标（car/truck/bicycle/motorcycle/pedestrian）帧占比 ≥ 5% |
| 标注精度 | 抽检 200 帧，bbox 与事件簇中心偏差 < 15 px |
| 可复现性 | 任意 episode 可按 seed + 配置重放复现 |

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| DVS 回调阻塞导致丢帧 | 回调只做 `put()`，落盘与投影放独立 worker 进程 |
| 事件量过大撑爆内存 | 攒批阈值（每 1 万事件或 50 ms）即写 h5 |
| 多实例 GPU 争抢 | 每实例限 `fixed_delta_seconds` 并错峰；或 `--quality-level Low` |
| 合成数据域差 | 保留 RGB 原始帧，可用 v2e/ESIM 对 RGB 再仿真真实噪声（热噪声、泄漏、低频截止）做数据增强 |
| 夜晚事件稀疏 | 低阈值预设 + 增加车灯/路灯照明场景占比 |

# 路侧多机位 DVS+RGB 事件流数据集说明

本文说明 `dvs_roadside_multicam` 数据集里**每个目录、每个文件、每个字段**的含义，
以你已经采集的那份数据（`E:\Projects\DVS_data\dvs_roadside_multicam`）为实例。

采集流程与算法设计见[路侧多机位 DVS+RGB 事件流数据集采集技术方案](路侧多机位DVS+RGB事件流数据集采集技术方案.md)。

## 0. 一分钟速览

```text
dvs_roadside_multicam/                 数据集根目录
├── sequences/                         所有采集序列（每条一个子目录）
│   └── sequence_000003/               一条序列 = 某路口机位组的一次完整采集
│       ├── cameras/cam_01/            一台相机的数据
│       │   ├── events.h5              事件流（HDF5）
│       │   ├── rgb/000000.png …       同步 RGB 帧
│       │   ├── timestamps.txt         每帧时间戳（微秒，相对序列起点）
│       │   └── annotations.json       逐帧检测标注（三类别 + 可见度 + 质量标记）
│       ├── snapshot.json              采集时的 actor 快照，投影可离线重算
│       ├── calibration/*.yaml         内外参、DVS/RGB 外参、时间偏移
│       ├── event_representations/     事件帧可视化输出目录（当前为空，预留）
│       └── meta/*.json                序列清单、DVS 参数、机位几何
├── calibration/rigs/                  本次用到的机位组 YAML + 杆位清单
├── tools/check_dataset.py             质检工具副本（可独立运行）
├── index_all.txt                      全量索引：每行一个**成功**的序列 ID
├── locations.csv                      位置时间索引：每条序列一行
├── unknown_blueprints.csv             靠兜底规则归类的蓝图（需人工确认）
├── batch_report.json                  最近一次批量采集的执行报告
├── annotation_report.json             事件统计汇总（stats 步骤写）
├── splits/{train,val,test}.txt        按路口划分的序列清单（split_dataset.py 写）
├── split_report.json                  划分报告：各类实例数/轨迹数/零事件比例
├── README.md / CHANGELOG.md / LICENSE.txt
```

一句话概括：**一条序列 = 一个路口机位组的一次采集**；序列内**每个机位一个目录**，
里面是「事件流 + 同步 RGB + 逐帧标注」三件套；序列级 `meta/` 和数据集级
`index_all.txt` / `locations.csv` 记录了这条序列**在哪、什么时候、采了多少**。

## 1. 数据集根目录

### 1.1 `sequences/`

所有序列，每条一个 `sequence_XXXXXX` 子目录（六位编号，全局递增）。
采集器**不做 train/val/test 划分**，需要划分时用 `tools/split_dataset.py`
（按路口分，见 §4.5）。

### 1.2 `calibration/rigs/`

本次采集实际使用的**机位组配置文件**留档：

- `Town10HD_Opt_j023.yaml`：机位组本体（地图、每台相机的坐标/朝向/FOV/DVS 参数、交通流、天气列表、路口位置）。
  采集器读的就是这个文件，所以它也是复现这次采集的最小输入。
- `poles.json`：布点台账。记录该地图共有多少根信号灯杆（`pole_count`）、分成几个机位组
  （`rig_count`），以及每台相机对应哪根杆（`cameras[].camera_id` → `pole_id`）。
  **相机是按杆位放的**——每个路口的每一根信号灯杆上各架一台相机。

### 1.3 `tools/`

`check_dataset.py` 的副本，可以脱离项目单独运行：

```powershell
python .\tools\check_dataset.py --dataset E:\Projects\DVS_data\dvs_roadside_multicam
```

它会检查：目录结构是否齐全、事件数与帧索引是否自洽、事件时间戳是否严格递增、
坐标是否越界、极性是否合法、RGB 帧数/时间戳/标注帧数三者是否一致、多机位时间戳是否一致、
每条序列在 `locations.csv` 里是否有位置时间记录；标注本身也会检查（bbox 有限值且宽高 > 0、
不越界、同一 actor 同帧不重复、`ignore` 必须有原因），相邻帧同一 actor 的框面积突变 > 6×
或边长突变 > 2.5× 只报警（WARNING）。

### 1.4 `index_all.txt`

全量索引，**每行一个成功序列的 ID**（`sequence_000003` 这样），没有表头。
只收录**磁盘上存在且 `meta/episode_manifest.json` 标记为 `completed`** 的序列；
每次登记新序列时按磁盘重建，删掉的序列会自动出索引（可用
`python tools/rebuild_index.py <数据集目录>` 立即重建存量索引）。

### 1.6 `batch_report.json`

最近一次**批量采集**的执行报告：用了哪个机位组目录、哪些地图、重复几遍、
总共几条成功几条失败、总耗时，以及每条序列的机位组、遍数、重试次数、耗时、
路口位置和**失败日志尾部**（最后 12 行控制台输出）。采集器用的是哪个 YAML、
清单和位置标注都写进了序列自己的 `meta/`，所以这个文件主要用来复盘批量任务。

### 1.7 `unknown_blueprints.csv`

本数据集里出现过的、**类别映射表没有显式列出**的蓝图（靠"其余 `vehicle.*` → car"
兜底规则归类），需要人工确认。重采之前可以用下面的命令导出一份完整清单核对：

```powershell
python .\tools\export_blueprints.py --host 127.0.0.1 --port 2000 --out-dir .
```

### 1.8 `annotation_report.json` / `splits/` / `split_report.json`

离线工具的产物（`tools/annotate_offline.py stats` 和 `tools/split_dataset.py` 写的，
不是采集器写的）：

- `annotation_report.json`：每个机位、每条序列的事件统计汇总，核心是**零事件框比例**
  （框里一个事件都没有的目标占比，用来筛掉无效样本）。
- `splits/{train,val,test}.txt`：按**路口**划分后的序列 ID 清单。
- `split_report.json`：划分报告——每个 split 的路口列表、各类别的实例数、轨迹数、
  零事件比例、框面积中位数。

### 1.9 `README.md` / `CHANGELOG.md` / `LICENSE.txt`

数据集自带的说明、变更记录和许可声明（首次采集时自动生成，之后不会被覆盖）。

## 2. 一条序列内部

以 `sequence_000003` 为例。

### 2.1 `cameras/cam_01/events.h5` — 事件流

HDF5 文件，三个组：

#### `/events/` — 事件本体（四列等长）

| 数据集 | 类型 | 含义 |
|---|---|---|
| `events/t` | `uint64` | 事件时间戳，**单位纳秒**，相对序列起点 |
| `events/x` | `uint16` | 像素列号（0–1279） |
| `events/y` | `uint16` | 像素行号（0–719） |
| `events/p` | `int8` | 极性：`1` = ON（变亮），`-1` = OFF（变暗） |

事件按时间排序；同一纳秒内出现重复时间戳时，会**依次加 1 ns** 保证严格递增
（见 `/meta/timestamp_tie_policy`）。本机位这 90 秒共 69,576,965 个事件，
平均每帧约 3.9 万个——所以用纳秒而不是微秒，否则同一微秒内会挤进好几个事件。

#### `/frames/` — 帧索引

| 数据集 | 类型 | 含义 |
|---|---|---|
| `frames/event_offsets` | `uint64` | 长度 = 帧数+1，第 i 帧的事件是 `events[*][offsets[i]:offsets[i+1]]` |
| `frames/event_count` | `uint64` | 每帧的事件数 |
| `frames/frame_id` | 字符串 | 帧 ID，格式 `{sequence_id}_{camera_id}_{帧号:06d}` |
| `frames/timestamp_us` | `uint64` | 每帧时间戳，**单位微秒**，相对序列起点 |

#### `/meta/` — 元数据

| 数据集 | 含义 |
|---|---|
| `sequence_id` / `episode_id` / `camera_id` | 序列与相机标识（与目录名一致） |
| `sensor_width` / `sensor_height` | 事件传感器分辨率（1280×720） |
| `time_origin_us` / `time_origin_ns` | 序列起点（仿真时刻），微秒与纳秒各存一份 |
| `integration_time_us` | 积分时间（50000 µs = 20 Hz） |
| `event_timestamp_unit` | 事件时间戳单位，`ns` |
| `event_timestamp_source_unit` | CARLA 给出的原始单位，`ns`（自动识别） |
| `polarity_encoding` | `1=ON,-1=OFF` |
| `timestamp_tie_policy` | 同刻事件的处理规则 |
| `timestamp_adjusted_event_count` | 为保持严格递增被调整过的事件数 |
| `town` / `weather` | 地图与天气 |
| `dvs_params` | 该相机的 DVS 参数（阈值、FOV、曝光模式…） |
| `camera_mount` | 相机安装位姿（世界固定） |
| `synced_rgb` | 对应 RGB 目录的相对路径 |

#### 读取示例

```python
import h5py
import numpy as np

with h5py.File("sequences/sequence_000003/cameras/cam_01/events.h5", "r") as h:
    offsets = h["frames/event_offsets"][:]
    timestamps = h["frames/timestamp_us"][:]          # 每帧时间戳（µs）
    # 第 0 帧的事件
    start, end = int(offsets[0]), int(offsets[1])
    frame0_t = h["events/t"][start:end]                # 纳秒
    frame0_x = h["events/x"][start:end]
    frame0_y = h["events/y"][start:end]
    frame0_p = h["events/p"][start:end]
    # 事件时间轴换算成微秒，与 RGB 帧时间对齐
    frame0_us = frame0_t / 1000.0
```

### 2.2 `cameras/cam_01/rgb/`

同步 RGB 帧，`000000.png`、`000001.png` … 连续编号，与 `timestamps.txt` 一一对应。
PNG 是 CARLA 渲染的原始画面（本机位 1800 帧 1280×720）。
采集时加了 `--rgb-format jpeg` 的数据集里存的是 `000000.jpg`（同样的编号规则，
JPEG q=90，体积约为 PNG 的 1/10）。
事件帧和 RGB 帧来自**同一个 CARLA tick**，所以同一帧的事件时间戳落在该帧
时间戳附近（曝光窗口内）。

### 2.3 `cameras/cam_01/timestamps.txt`

每行一个整数：该帧时间戳（**微秒**，相对序列起点），严格递增。
本机位从 `100000` 开始，每帧 +`50000`（20 Hz）。

### 2.4 `cameras/cam_01/annotations.json`

逐帧检测标注（`car` / `motorcycle` / `pedestrian`），结构：

```json
{
  "sequence_id": "sequence_000003",
  "camera_id": "cam_01",
  "sensor_width": 1280,
  "sensor_height": 720,
  "class_map_version": "2.0",
  "classes": { "car": 0, "motorcycle": 1, "pedestrian": 2 },
  "frames": [
    {
      "frame_id": "sequence_000003_cam_01_000000",
      "timestamp_us": 100000,
      "integration_time_us": 25000,
      "annotations": [
        {
          "id": 1,
          "category": "car",
          "category_id": 0,
          "subtype": "sedan",
          "blueprint_id": "vehicle.audi.a2",
          "bbox": [843, 54, 100, 72],
          "truncated": false,
          "occluded": false,
          "difficult": false,
          "ignore": false,
          "visibility": 0.97,
          "visible_px": 3211,
          "visible_bbox": [845, 56, 941, 124],
          "occupancy": 0.53,
          "actor_id": 397,
          "speed_mps": 0.98,
          "stationary": false,
          "quality_flags": []
        }
      ],
      "ignored_annotations": []
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `bbox` | `[x, y, width, height]`，像素，左上角原点 |
| `category` / `category_id` | `car`(0) / `motorcycle`(1) / `pedestrian`(2) |
| `subtype` | 汽车子类：`sedan`/`suv`/`van`/`bus`/`truck`/`emergency`，认不出来的记 `other` |
| `blueprint_id` | CARLA 蓝图 ID，类别可追溯 |
| `actor_id` | CARLA actor 编号——**跨机位关联同一目标就用它** |
| `speed_mps` | 该目标瞬时速度（米/秒） |
| `stationary` | 速度低于阈值（默认 0.1 m/s）时为 `true` |
| `truncated` | 框**被图像边界裁切**时为 `true`（穿过近裁剪面的目标整条丢弃，不算截断） |
| `occluded` / `difficult` | 遮挡 / 困难样本标记，由可见度和小面积规则决定 |
| `ignore` / `ignore_reason` | 是否忽略及原因：`low_visibility`（可见度过低）、`beyond_detection_range`（超出相机有效探测范围）、非目标类别 |
| `distance_m` | 由投影框高度反推的目标距离（米），与朝向无关 |
| `visibility` | 可见度 0–1（实例分割算出的可见像素 / 3D 框投影面积，再按类别填充率归一） |
| `visible_px` / `visible_bbox` / `occupancy` | 可见像素数、可见部分的紧框、占投影框的比例 |
| `quality_flags` | `tiny`（框 < 400 px²）/ `low_event`（框内零事件）/ `static`（静止）/ `ignored_low_visibility` / `severe_occlusion` / `beyond_detection_range` |
| `event_count` / `event_density` / `active_pixel_ratio` / `on_off_ratio` | 框内事件统计，`tools/annotate_offline.py stats` 写回 |
| `id` | 该帧内的目标编号（仅本帧有效） |

`ignored_annotations[]` 放被忽略的目标（自行车等非目标类别），带 `ignore_reason`。
`ignore=true` 与 `low_event` 的样本**保留在文件里**，由加载器按配置过滤。

#### 有效探测范围（`beyond_detection_range`）

太远的目标在画面上只有几个像素，相机采不到足以定位的事件，留着只是噪声标签。
判据有两条，任意一条不满足就标 `ignore=true`：

| 判据 | 默认值 | 依据 |
|---|---|---|
| 投影短边像素数 | ≥ 16 px | DVSense DVSync 的 DVS 面板 1 MP、像元 1.45 μm、FOV 70°~130°，角分辨率约 0.055°~0.10°/px，人眼在同样角分辨率下也看不清轮廓。实测（本项目 events.h5）：运动目标短边 <10 px 时仅 10%~39% 的帧有事件，10~18 px 为 19%~40%，18~24 px 升到 67%~74%，≥24 px 稳定在 75%~100% |
| 推算距离 | ≤ 120 m | 对应 DVSync 标称 FOV 下车辆的有效观测尺度；150 m 外的车只有几个像素高 |

用**投影短边**而不是纯距离做主判据：同样的距离，正面朝相机的车短边大、
侧向的车短边小，只按距离过滤会误伤近距离的大目标。

阈值可用 `--min-detect-px` / `--max-detect-distance` 调整，
离线重投影时用同样的参数（`tools/annotate_offline.py project`）以保证结果一致。

同一路口的多台相机看向同一个 actor，`actor_id` 相同 → 可以直接做跨机位目标关联。

> 2026-11 之前采集的旧序列里，`category` 是 `vehicle` / `walker` 二分类，也没有
> `blueprint_id`、摩托车类别和可见度字段（`occluded`/`difficult` 恒为 `false`），
> 只能当二分类基线用。

### 2.5 `snapshot.json` — 采集时的 actor 快照

一条序列一个文件，记录**不可重算**的信息：每帧每个 actor 的 4×4 世界矩阵、
蓝图 ID、类别、速度、静止标记，以及每个机位的可见像素统计（`visible_px`、
可见紧框、投影面积）。实例分割图本身不保存。

有了它，投影/可见度代码改了不必重采：

```powershell
python .\tools\annotate_offline.py project --sequence .\dvs_roadside_multicam\sequences\sequence_000003
```

离线重投影走的是和在线完全相同的代码，结果逐字段一致（`tools/test_annotation.py` 覆盖）。

### 2.6 `calibration/` — 标定文件

| 文件 | 内容 |
|---|---|
| `intrinsics_dvs.yaml` | DVS 内参：`fx/fy/cx/cy`、分辨率、无畸变 |
| `intrinsics_rgb.yaml` | RGB 内参（本设置下与 DVS 相同：同位、同分辨率、同 FOV） |
| `extrinsics_world.yaml` | 每台相机的世界外参：`camera_to_world_matrix`（4×4）、`location_m`、`rotation_degrees` |
| `dvs_rgb_extrinsic.yaml` | DVS 与 RGB 的相对外参（此处为单位阵 + 零平移，标定状态 `theoretical_same_transform_not_hardware_measured`） |
| `time_offset.yaml` | 事件到 RGB 的时间偏移（`events_to_rgb_offset_us: 0`，对齐方式 `same CARLA simulation tick`，`hardware_measurement: false`） |

> ⚠️ 这些标定是**仿真内的理论值**，不是硬件实测标定。CARLA 里 DVS 和 RGB 同位同 tick，
> 所以偏移为 0、外参为单位阵；拿去做真实相机的标定参考时不能直接照搬。

### 2.7 `meta/` — 序列级元数据

| 文件 | 内容 |
|---|---|
| `episode_manifest.json` | 序列总清单（下面展开） |
| `dvs_params.json` | 每台相机的 DVS 参数 + CARLA 实际接受的曝光模式 |
| `rig_geometry.json` | 每台相机的 `camera_to_world_matrix` 和 `camera_to_reference_matrix`（相对机位组第一台相机） |

`episode_manifest.json` 关键块：

- `location`：**采集位置**
  - `town` / `map_name` / `junction_id` / `junction_center_m` / `geo` / `aim`
  - `cameras.{cam_XX}`：`location_m`（世界坐标米）、`rotation_degrees`（yaw/pitch/roll，度）、`geo`
  - 坐标约定：CARLA 中 **yaw 0° = +X，90° = +Y，负 pitch = 俯视**
- `capture_time`：**采集时间**
  - `started_at_utc` / `started_at_local` / `timezone` / `ended_at_utc`
  - `elapsed_wall_s`（墙钟耗时）/ `simulation_start_s` / `simulation_end_s`（仿真时间起止）
  - `frame_count` / `fps`
- 其余：`weather`、`seed`、`fps`、`fixed_delta_seconds`、`camera_ids`、`cameras[]`（每台的位姿与 DVS 参数）、
  `spawned_traffic`（实际生成的汽车/摩托车/行人数）、`event_counts`（每机位事件数）、`timestamp_adjusted_event_counts`、
  `status`（`completed` / `failed` / `in_progress`）、`error`（失败原因）。
- 标注相关：`class_map_version` / `classes`（类别映射表版本与类别编号）、
  `instance_segmentation`（实例分割是否开启、降采样倍数）、
  `annotation_validation`（每机位各类别的轨迹数、运动/静止轨迹数、平均位移——行人有没有真动的验收项）、
  `blueprints_seen` / `blueprints_by_fallback`（本序列出现过的蓝图，以及靠兜底规则归类的那些）。

### 2.8 `event_representations/`

预留给「事件帧」可视化输出（例如把一段事件累积成帧图）。当前采集流程不写这个目录，**是空的**。

## 3. 采集日志目录 `logs/`

每次采集自动在项目根目录建一个日志子目录（`logs/<日期-时间>_<地图>/`），
记录**这次采集的时间、机位、数量、事件量**：

```text
logs/
├── index.csv                              采集历史总表：每次采集一行
└── 20261026-160638_Town10HD_Opt/
    ├── run.json                           结构化运行摘要
    ├── run.log                            完整控制台输出（含采集器逐帧进度）
    └── sequences.csv                      每条序列一行
```

- `run.json`：起止时间（UTC + 本地）、耗时、主机/端口、机位组目录与文件列表、地图、
  输出目录、重复遍数、相机数/帧数/帧率/车流/天气参数、成功失败数、事件总量、本次命令行。
- `run.log`：控制台原样落盘（含子进程采集器的「采集进度 N/M 帧」和每 10 条序列的累计汇总）。
- `sequences.csv`：`sequence_id, rig, repeat, attempt, status, junction_id, camera_count,
  frame_count, total_events, weather, started_at_local, elapsed_s`。
- `index.csv`：`run_id, started_at_local, ended_at_local, towns, rig_dir, rig_count, repeat,
  sequences, succeeded, failed, total_events, elapsed_s, log_dir`，**每次采集追加一行**。

用 `collect_batch.py --log-dir <目录>` 换位置；向导里也会问。

## 4. 常见问题

### 4.1 事件时间戳的单位（重要）

**当前（2026-10-26 之前采集的）文件里，`events/t` 的单位被写错了。**

CARLA 0.9.16 的 DVS 传感器给出的原始事件时间戳是**纳秒**，而当时的写入器按微秒
减去了序列起点，导致存下来的时间轴整体偏了 `999 × 起点微秒`（本数据集是 294 秒）。
后果是：**事件时间和 RGB 帧时间对不上**（事件比帧时间大 3 个数量级），
按事件时间戳切帧会全错。

已经做的处理：

- 写入器已改为**统一用纳秒**（`meta/event_timestamp_unit = ns`），并自动识别 CARLA
  给的原始单位（`meta/event_timestamp_source_unit`）；`tools/test_event_timestamps.py`
  覆盖了这条链路。
- 质检工具 `check_dataset.py` 新增了「事件时间必须落在该帧曝光窗口内」的检查，
  单位错会直接报错。
- 历史数据用下面的命令修复（把错位的时间轴平移到正确的纳秒轴，只动 `events/t`，
  不改其它任何数据；修完 `meta` 里的单位标记也会同步更新）：

```powershell
python .\tools\fix_event_timestamps.py --dataset E:\Projects\DVS_data\dvs_roadside_multicam --dry-run
python .\tools\fix_event_timestamps.py --dataset E:\Projects\DVS_data\dvs_roadside_multicam
```

> `sequence_000001/cam_02` 的事件时间戳**不是严格递增**：这条采集在某个时刻
> 传感器回调乱序了，常量平移救不回来（修复工具会把它标成 `unknown` 不动）。
> 这条序列的标注本身可用，事件切片会有问题，建议重采这一条。

### 4.2 失败/中断的序列

失败序列的 `meta/episode_manifest.json` 里 `status` 是 `failed` 或 `in_progress`，
`error` 字段写着原因。它们**不在** `index_all.txt` / `locations.csv` 里，
也缺少 `annotations.json` 和标定文件。保留它们只是为了排查，序列编号不会被复用。

### 4.3 地理坐标是什么意思

`geo_latitude/longitude` 来自 CARLA 地图自带的地理参考（`map.transform_to_geolocation()`），
是**该地图内部一致的一套相对定位**，不等于真实城市的经纬度（数值在 0 附近就是这个原因）。
它的用途是给不同路口一个可比较的相对位置；要做真实地理配准必须另外引入地图配准。

### 4.4 标定是理论值

见 §2.5。DVS/RGB 同位、零时间偏移是 CARLA 的仿真假设，不是实测标定结果。

### 4.5 怎么划分训练/测试

采集器不做划分，用工具划：

```powershell
python .\tools\split_dataset.py --dataset E:\Projects\DVS_data\dvs_roadside_multicam
```

按**路口**分而不是按帧随机分——同一个路口的不同序列外观高度相似，按帧分会让
同一批目标同时出现在训练集和测试集里，指标会虚高。比例 70/15/15，测试集另外
保证至少含一条夜间序列（必要时把整个路口挪进测试集）。结果写
`splits/{train,val,test}.txt` 和 `split_report.json`。

也可以按 `locations.csv` 自己过滤（例如按 `capture_started_at_local` 分时段、
按 `weather` 分昼夜），再把 `sequence_id` 列表喂给你的训练脚本。

## 5. 常用代码片段

```python
import json
from pathlib import Path

import h5py
import numpy as np

root = Path("dvs_roadside_multicam")
sequence = root / "sequences" / "sequence_000003"
camera = sequence / "cameras" / "cam_01"

# 1) 位置与时间
manifest = json.loads((sequence / "meta" / "episode_manifest.json").read_text(encoding="utf-8"))
print(manifest["location"]["junction_id"], manifest["capture_time"]["started_at_local"])

# 2) 事件 + 帧索引
with h5py.File(camera / "events.h5", "r") as h:
    offsets = h["frames/event_offsets"][:]
    frame_ts_us = h["frames/timestamp_us"][:]
    for index in range(len(frame_ts_us)):
        start, end = int(offsets[index]), int(offsets[index + 1])
        t_ns = h["events/t"][start:end]      # 纳秒
        x = h["events/x"][start:end]
        y = h["events/y"][start:end]
        p = h["events/p"][start:end]        # 1=ON, -1=OFF
        # t_ns / 1000 就是与 frame_ts_us[index] 同一时间轴的微秒值

# 3) 逐帧标注
annotations = json.loads((camera / "annotations.json").read_text(encoding="utf-8"))
print(annotations["classes"])          # {"car": 0, "motorcycle": 1, "pedestrian": 2}
for frame in annotations["frames"]:
    for obj in frame["annotations"]:
        print(frame["timestamp_us"], obj["category"], obj["bbox"], obj["actor_id"], obj["speed_mps"])

# 4) 只要可训练样本：过滤零事件框、忽略框和困难样本
def usable(obj):
    if obj.get("ignore") or obj.get("difficult"):
        return False
    return "low_event" not in obj.get("quality_flags", [])

samples = [
    (frame["timestamp_us"], obj)
    for frame in annotations["frames"]
    for obj in frame["annotations"]
    if usable(obj)
]
```
